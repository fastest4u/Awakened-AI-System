# Task 12C3 branch-bound source binding design

**Status:** Written for user review; not yet approved for implementation
**Date:** 2026-09-25
**Parent:** [V2 shadow migration and compatibility parity design](2026-09-09-v2-shadow-migration-and-compatibility-parity-design.md), [Task 12 plan](../plans/2026-09-09-v2-shadow-migration-and-compatibility-parity.md)
**Decision already approved in conversation:** Support an authenticated branch-bound V1 source in the private rehearsal, rather than permanently restricting rehearsal to unbranched sources. This document specifies how; conversational approval does not approve this written text or authorize implementation.

## 1. Purpose and current failure

Task 12C3's private compiled rehearsal accepts `expectedBinding.branchRef` and the read-only C1 preflight authenticates it against the sealed V1 source. Its Task 11F runner currently reconstructs the expected source binding from the isolated target's `ProjectContext`. That target is truthfully non-Git, so the reconstructed `branchRef` becomes `null`. A valid branch-bound copy can pass C1 but fail during the first operational run after reservation and target creation. This is a source-versus-target identity conflation, not evidence that the source's Git branch is invalid.

The desired outcome is for both unbranched and branch-bound sealed sources to complete the same genuine three-clean-plus-fourth-no-op rehearsal, while the isolated target remains non-Git, source bytes remain read-only, V1 remains the only production caller, and no Git metadata is fabricated.

## 2. Selected contract

Add one required internal `expectedSourceBinding: ProjectBinding` field to `V2ShadowMigrationRunInput`. It is the exact seven-field projection binding (`projectId`, `vaultId`, `storeId`, `workspaceId`, `branchScopeId`, `branchRef`, `sessionId`) requested by the caller, not a `GitWorkspaceSnapshot` and not an independently asserted live Git HEAD. The runner's strict own-data input capture and exact key list include this field. Missing, extra, accessor-backed or malformed input fails under the existing redacted typed-error boundary; changing the caller's original object after capture cannot change the runner's captured value.

Before any target mutation, the runner applies the same exact field/domain constraints as the existing V1 source-binding decoder: lowercase UUIDv4 or legacy SHA-256 project/vault/store IDs, SHA-256 workspace ID, nullable source-verifier-accepted UUID branch scope, nullable nonempty NUL-free branch ref, and null session. This is a bounded validation at the runner input boundary, not a relaxation or new public decoder. Its project, vault, store and workspace IDs must equal those in `targetContext.binding`; `branchScopeId` must equal `targetContext.branchScopeId ?? null`. If `targetContext.workspace.kind === "git"`, its actual `branchRef` must also equal `expectedSourceBinding.branchRef`, preserving the previous Git-target invariant. A non-Git isolated target has no branch-ref equality requirement: its source branch comes only from the explicit source binding and is subsequently authenticated by the sealed copy. Invalid shape is `MIGRATION_SOURCE_INVALID`; conflicting identities are `MIGRATION_IDENTITY_CONFLICT`. Both are redacted, nonzero, and precede target writes.

Pass the captured `expectedSourceBinding` unchanged to the existing `verifyV1SourceCopy`. That verifier compares all six manifest binding fields, authenticates the stored event chain and source-file identities, and owns its current deadlines and rechecks. Do not infer a branch from the target, trust an unverified manifest field by itself, normalize away a mismatch, or use a late retry with a different binding. Task 12C3 passes its already C1-verified `preflightInput.expectedBinding` as this field on all four invocations; final fresh C1 still compares source/corpus bytes and identities before evidence publication.

The isolated target remains a `non-git` workspace. Its append context is for target migration events, not a claim about the source's Git repository. Source event scope, including branch identity, is preserved inside the authenticated imported source records and checked by the existing projection/parity path. No synthetic Git directory, HEAD, branch snapshot or metadata is created. The branch string in a sealed source proves only that sealed copy's authenticated binding, not current live Git state or operator approval provenance.

## 3. Alternatives rejected

- Creating a Git-shaped target solely to make the old inference return a branch would introduce synthetic repository metadata and make clean-run determinism depend on Git commits. It would conflate target and source authority again.
- Adding a branch override to the shared EventStore/append pipeline would broaden a security-sensitive public write boundary. Imported migration event wrappers can remain target-scoped; the source record already carries its own binding.
- Refusing every non-null source `branchRef` before reservation would contain the late-write symptom but fail the approved branch-capable rehearsal contract.

## 4. Scope and verification

The intended implementation scope is `src/orchestrator/migration/v2-shadow-migration-runner.ts`, `src/orchestrator/migration/v2-shadow-migration-rehearsal.ts`, `tests/support/v2-shadow-migration-fixture.ts`, `tests/v2-shadow-migration-runner.test.ts`, and `tests/v2-shadow-migration-rehearsal.test.ts`. The pre-existing uncommitted C3 retry-delta fix in rehearsal source/test remains a separate reviewed correction and must not be discarded. No public entry point, EventStore, importer, source verifier, evidence schema, schema registry, CI contract, dependency or live PROD state changes are authorized by this addendum. If a genuine branch-bound fixture cannot be produced within the stated test scope using production writers, stop and obtain a revised design ruling rather than editing raw event rows, manufacturing a manifest, or weakening the verifier.

Test-driven proof must first show the current late failure with a real sealed branch-bound copy, then prove the fixed compiled command succeeds with that copy through three independent clean runs and a fourth semantic no-op. The fixture must obtain branch scope/ref through the production Git/lifecycle writer, seal the corresponding full source-bound corpus, and check source/corpus identities and imported branch provenance before and after. Add direct runner tests for missing/malformed binding and mismatched project/store/workspace/branch scope, a real Git-target branch disagreement, and the existing unbranched path. Negative CLI inputs must refuse before reservation, package or target mutation when their mismatch is knowable at entry. Do not present a hand-edited source manifest or a config-only branch string as positive branch support.

After focused RED/GREEN, run a fresh test build and the exact serial three-file Task 12 gate (`v2-shadow-migration-rehearsal`, `v2-shadow-migration-runner`, `v2-shadow-importer`), then typecheck, production build, built smoke, diff/hash checks and independent specification/quality/security review on the final scoped commit. Any retained success evidence uses a new absent test-only destination; preserve prior finalized evidence and the old failed reservation. The historical 236/236 gate applies to the earlier commit and is not a substitute for this final-source gate. The full suite's known Task 13 contract failures remain separate; this addendum does not label Task 12, Slice 2 or V2 production-ready.
