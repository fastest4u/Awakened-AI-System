# Project Memory V2 Phase 2: AI + IDE Acceleration & Deep Integration Design Spec

**Date:** 2026-10-21  
**Project:** Awakened-AI-System (`Project Memory V2`)  
**Status:** Approved for Implementation

---

## 1. Problem Statement & Goals

Phase 1 of Project Memory V2 Awakening delivered cross-session visibility, hybrid retrieval, autonomous `memory_awaken`, active `memory_selfCheck`, structured checkpoints, and multi-project `projectRoot` routing. To make Project Memory V2 work at peak efficiency with AI agents and IDEs (Google Antigravity, Cursor, VS Code, Codex), six concrete bottlenecks remain:

1. **Multi-Round-Trip Startup Latency & Parameter Friction**: Starting a task currently requires 3–4 sequential MCP tool calls (`memory_sessionStart` -> `memory_awaken` -> `memory_contextPack` -> `memory_selfCheck`), costing 3–5 seconds of IDE round-trip latency. In addition, AI agents frequently pass parameter synonyms (`noteId` vs `recordId` vs `id`, `targetState` vs `targetStatus`, `evidence` array vs `content` string, `verificationMethod: "policy" | "test"`) that cause preventable validation errors.
2. **Lack of File-Path & Code-Symbol Memory Graph**: When an AI agent inspects or edits specific files (e.g., `src/v2/public-tools.ts`), `memory_selfCheck` and `memory_contextPack` need to match notes and checkpoints by exact normalized file paths and code symbols mentioned in historical ADRs, Mistakes, Insights, and Checkpoints.
3. **Lexical-Only Tokenization for Thai + Technical Queries**: While 4-gram Jaccard fallback handles unspaced Thai substrings, Node.js 24 provides native `Intl.Segmenter("th", { granularity: "word" })`. Combining dictionary-based Thai word segmentation with IDF-weighted BM25 scoring dramatically improves ranking precision for mixed Thai/English technical queries.
4. **Missing MCP Resources & MCP Prompts in `src/v2/app.ts`**: `runV2Server` currently exposes only `capabilities: { tools: {} }`. Exposing MCP `resources` (`memory://current/awaken`, `memory://current/rules`, `memory://current/adrs`, `memory://current/mistakes`) and MCP `prompts` (`awaken-session`, `pre-flight-check`, `session-handoff`) allows IDEs to embed live memory context and trigger workflows natively.
5. **Rebuild Friction (`FRESH_START_BUILD_MISMATCH`) in Active IDEs**: Rebuilding `dist/v2.js` changes `buildIdentityHash`. When opted in via `MEMORY_V2_AUTO_SYNC_BUILD=1` (generated by `bootstrap-project` and IDE configs), a verified `dist/v2.js` deployment (whose `inspectV2Build()` passes) should auto-heal `fresh_start_releases.build_identity_hash` on startup while preserving strict fail-closed behavior when `MEMORY_V2_AUTO_SYNC_BUILD` is unset.
6. **IDE System-Prompt Rule Synchronization (`.antigravity/MEMORY_RULES.md`)**: When binding ADRs or Mistakes are recorded or promoted, automatically materializing a concise `.antigravity/MEMORY_RULES.md` file in the project root allows IDEs and agents to see critical project constraints immediately.

## 2. Architecture & Component Design

### 2.1 One-Call Atomic `memory_sessionStart` & Ergonomic Parameter Normalization (`src/v2/public-tools.ts`)
- **`memory_sessionStart` Auto-Bundle**:
  - By default (unless `includeContext: false`), `memory_sessionStart` returns:
    - `sessionId`, `conversationId`, `status`, `mode`
    - `awaken`: full autonomous awakening payload (`continuity`, `workspaceState`, `governanceAlerts`, `autonomousAgenda`)
    - `contextPack`: ranked relevant project notes for `taskSummary` / `contextArea` / `query`
    - `selfCheck`: pre-flight risk assessment (`riskLevel`, `pastMistakesToAvoid`, `bindingADRs`, `preFlightChecklist`) when `plannedFiles` or `taskSummary` is supplied
- **Universal Parameter Synonym Support**:
  - `#handleWriteGovernedNote` returns `id`, `noteId`, and `recordId` (all set to `responseReceipt.recordId`).
  - `#handlePromote`, `#handleSupersede`, `#handleRetract`, `#handleExpire`, `#handleForgetEvidence` accept `args.recordId ?? args.id ?? args.noteId`.
  - `#handlePromote` accepts `args.targetStatus ?? args.targetState` (mapping `"approved"` / `"active"` / `"verified"` -> `"verified"`) and normalizes `verificationMethod` (`"policy"`, `"test"`, `"automated"` -> `"automated-check"`; `"manual-review"`, `"operator-approved"` -> `"user-confirmed"`).
  - `#handleRecordEvidenceBatch` accepts either `content: string` or `evidence: Array<{ evidenceType?: string; ref?: string; summary?: string } | string>`, serializing structured evidence items into the retained evidence frame.

### 2.2 File-Path & Code-Symbol Memory Graph (`src/v2/public-tools.ts`)
- Add `#extractFilePathsAndSymbols(text: string): { filePaths: string[]; symbols: string[] }`:
  - Extracts relative/repo file paths (e.g., `src/v2/public-tools.ts`, `tests/foo.test.ts`, `app/Http/Controllers/UserController.php`) normalized to forward slashes, and code identifiers (`camelCase`, `PascalCase`, `#privateMethod`, `snake_case` functions).
- Enrich `#listProjectNotesFromProjection()` items with `filePaths` and `symbols`.
- In `#handleSelfCheck` and `#handleContextPack`:
  - Accept `plannedFiles` / `filesTouched` (`string[]`).
  - Boost any ADR, Mistake, or Insight whose extracted `filePaths` or `body` matches the basename or normalized relative path of `plannedFiles` by `+250` score, and return `fileMatchedNotes` in `memory_contextPack` and `fileSpecificWarnings` in `memory_selfCheck`.

### 2.3 Native Thai `Intl.Segmenter` + BM25-Style IDF Hybrid Scoring (`src/v2/public-tools.ts`)
- Add `#tokenizeMultilingual(text: string): string[]`:
  - Uses `new Intl.Segmenter("th", { granularity: "word" })` when available in the runtime to segment Thai words accurately alongside Latin/numeric tokens, filtering stopwords and single-character noise.
- Upgrade `#scoreHybridNoteMatch(note, rawQuery, extraTerms, corpusDocFreq?, totalDocs?)`:
  - Computes token matches across `title`, `summary`, `normalizedKey`, `filePaths`, `symbols`, and `body`.
  - Applies IDF weighting ($\ln(1 + \frac{N - df + 0.5}{df + 0.5})$) when corpus statistics are provided so rare technical terms or specific Thai words outweigh common terms, while retaining the 4-gram Jaccard fallback for compound Thai phrases.

### 2.4 MCP Resources & MCP Prompts (`src/v2/app.ts`)
- Upgrade `Server` capabilities in `runV2Server()` to `{ capabilities: { tools: {}, resources: {}, prompts: {} } }`.
- Register `ListResourcesRequestSchema` and `ReadResourceRequestSchema`:
  - `memory://current/status` -> JSON of `foundation.status()`
  - `memory://current/awaken` -> JSON of `memory_awaken` (when store is active)
  - `memory://current/rules` -> Markdown summary of active binding ADRs and Mistakes
- Register `ListPromptsRequestSchema` and `GetPromptRequestSchema`:
  - `awaken-session`: Prompt template instructing the agent to run `memory_sessionStart` with task summary and follow the returned `autonomousAgenda`.
  - `pre-flight-check`: Prompt template instructing the agent to run `memory_selfCheck` with `plannedFiles`.

### 2.5 Opt-In Auto-Heal Build Identity Sync (`src/v2/composition.ts` & `src/v2/admin.ts`)
- In `createV2Foundation(input, options)`:
  - When `options?.autoHealBuildSync === true` or `process.env.MEMORY_V2_AUTO_SYNC_BUILD === "1"`, after `inspectV2Build(options?.entryUrl)` succeeds (proving all 5 V2 build artifacts match `dist/v2-build.json`), if the stored release row's `build_identity_hash` differs from `measuredBuild`, update `fresh_start_releases.build_identity_hash` inside an `IMMEDIATE` transaction (dropping and recreating `fresh_start_releases_no_update`).
  - Include `"MEMORY_V2_AUTO_SYNC_BUILD": "1"` in client configs generated by `bootstrap-project` in `src/v2/admin.ts`.

### 2.6 Auto-Sync `.antigravity/MEMORY_RULES.md` (`src/v2/public-tools.ts`)
- Add `#syncIdeMemoryRulesFile()` called after `#handleWriteGovernedNote` (for `adr` and `mistake`) and `#handlePromote`:
  - Queries top active/approved/candidate `adr` and `mistake` notes from the projection and writes a concise, deterministic Markdown summary to `<projectRoot>/.antigravity/MEMORY_RULES.md` (only if `<projectRoot>/.antigravity` exists or when explicitly enabled, never touching `v1ArchiveRoot`).
